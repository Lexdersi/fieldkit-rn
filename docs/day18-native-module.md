# Day 18 – NativeDeviceInfo, a Turbo Native Module

`getBatteryLevel(): number`, `getModel(): string`, `isEmulator(): boolean`, synchronous over JSI,
shown on the Settings tab.

## Why a local package and not android/ + ios/ directly

The app uses Continuous Native Generation: `android/` and `ios/` are regenerated by
`expo prebuild` and are gitignored. Native code written there would be lost on the next run. So the
module is a local package that autolinking picks up like any npm library:

```
modules/native-device-info/
  package.json                 codegenConfig (name, type: modules, Java package, iOS provider)
  src/NativeDeviceInfo.ts      the spec
  src/index.ts                 JS wrapper: -1 → null, null when not linked
  android/build.gradle         applies com.facebook.react → runs Codegen for this library
  android/src/main/java/com/fieldkit/deviceinfo/
    NativeDeviceInfoModule.kt  subclasses the generated NativeDeviceInfoSpec
    NativeDeviceInfoPackage.kt BaseReactPackage, ReactModuleInfo(isTurboModule = true)
  ios/RCTNativeDeviceInfo.h/.mm   implements the generated protocol, returns the JSI object
  native-device-info.podspec   install_modules_dependencies(s)
  react-native.config.js       exact package class for autolinking
```

Root `package.json`: `"@fieldkit/native-device-info": "file:modules/native-device-info"`.

Note: the Expo docs for SDK 57 only cover the Expo Modules API, which has no Codegen spec. The
lesson (and capstone Q4) is about Codegen, so this follows the React Native library layout instead.

## Spec line → generated artefact (Android, verified 12 Oct)

Generated by `./gradlew assembleRelease` (the run got this far, then stopped for low memory) into
`modules/native-device-info/android/build/generated/source/codegen/`:

| Spec | `java/.../NativeDeviceInfoSpec.java` | `jni/NativeDeviceInfoSpec-generated.cpp` |
|---|---|---|
| filename `NativeDeviceInfo.ts` + `get<Spec>('NativeDeviceInfo')` | `public static final String NAME = "NativeDeviceInfo"`, `getName()` | `if (moduleName == "NativeDeviceInfo")` in `NativeDeviceInfoSpec_ModuleProvider` |
| `getBatteryLevel(): number` | `@ReactMethod(isBlockingSynchronousMethod = true) public abstract double getBatteryLevel();` | host function → `invokeJavaMethod(rt, NumberKind, "getBatteryLevel", "()D", …)` |
| `getModel(): string` | `public abstract String getModel();` | host function with `StringKind`, `"()Ljava/lang/String;"` |
| `isEmulator(): boolean` | `public abstract boolean isEmulator();` | host function with `BooleanKind`, `"()Z"` |
| `extends TurboModule` | `extends ReactContextBaseJavaModule implements TurboModule` | `class NativeDeviceInfoSpecJSI : public JavaTurboModule` (`jni/NativeDeviceInfoSpec.h`) |
| whole file | n/a | `schema.json`: the parsed spec everything above is generated from |

`codegenConfig.type` is `modules`, yet Codegen still writes empty Fabric files under
`jni/react/renderer/components/` (Props, ShadowNodes…). They have no content for a module.

`NativeDeviceInfoModule.kt` compiled against that generated class in the same build
(`:fieldkit_native-device-info:compileReleaseKotlin`). A spec method without a Kotlin override is a
compile error, which is the point of Codegen.

iOS: the same spec produces a `NativeDeviceInfoSpec` protocol and `NativeDeviceInfoSpecJSI` during
`pod install`. **Not generated or compiled here**: no Mac. The `.mm` is written against the
documented shapes (sync `number`/`boolean` → `NSNumber *`, `string` → `NSString *`) and is unverified.

## Decisions

- **`number` can't be nullable** in a spec. Battery "unknown" (iOS Simulator, or Android devices
  that don't report capacity) is `-1`, mapped to `null` in `index.ts`.
- **`TurboModuleRegistry.get`, not `getEnforcing`.** In Expo Go, on web and in Jest the module
  doesn't exist. `getEnforcing` throws at import time and takes the Settings screen down with it;
  `get` returns null and Settings says "not linked".
- **iOS battery**: `batteryMonitoringEnabled` is off by default and is a main-thread API. It's
  switched on in `init` on the main queue, so the very first read can still say unknown.
- **isEmulator on Android** is a heuristic (`Build.FINGERPRINT`, `HARDWARE`, `PRODUCT`); there's no
  official API. It covers the stock emulator images, not every third-party emulator.
